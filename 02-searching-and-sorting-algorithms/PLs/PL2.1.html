NRO. PRÁCTICA: PL2.1 TÍTULO: Ordenamiento de estudiantes con Comparator y Comparable
OBJETIVOS
  • Implementar el orden natural de una clase mediante Comparable<Estudiante>.
  • Construir criterios externos con Comparator<Estudiante>, expresiones lambda y referencias a métodos.
  • Aplicar criterios compuestos, desempates y sentidos ascendentes y descendentes.
  • Verificar estabilidad, conservación de registros y preservación del orden original.
  • Documentar resultados reproducibles en un repositorio Git.
CONTEXTO

La coordinación académica necesita consultar un mismo grupo de estudiantes mediante diferentes órdenes: código, nombre, nota, edad y carrera. Cada consulta debe ordenar una copia de la lista y conservar intacta la secuencia original.

El código define el orden natural. Los demás órdenes se implementan como comparadores externos, sin modificar compareTo() para cada consulta.

RECURSOS

Computador con JDK, editor o IDE, Git y una cuenta para alojar el repositorio remoto. Registrar en el README la versión del JDK utilizada.

Trabajo individual en Java, sin Maven, Gradle ni dependencias externas. Utilizar las bibliotecas estándar.

INSTRUCCIONES
  1. Crear la clase Estudiante con los atributos codigo, nombre, edad, nota y carrera.
  2. Usar String para los textos, int para edad y double para nota. Los textos son no nulos, los códigos únicos, las edades positivas y las notas finitas entre 0 y 10.
  3. Incorporar constructor, getters y toString(). Mantener los atributos inmutables para evitar cambios durante el ordenamiento.
  4. Implementar Comparable<Estudiante> con código ascendente como orden natural.
  5. Utilizar List.sort() o Collections.sort(). Cada consulta debe partir de una nueva ArrayList con los datos originales.
  6. Comparar los textos con el orden de String.compareTo(), sensible a mayúsculas. No aplicar normalización ni reglas regionales.
  7. No comparar números mediante restas ni convertir diferencias de notas a int. Utilizar comparaciones seguras o los constructores de comparadores correspondientes.
  8. Mostrar el identificador de cada consulta, su criterio y los registros completos en el orden obtenido.
  9. Publicar el proyecto en un repositorio Git remoto. El enlace debe permitir al docente acceder a la entrega.

ACTIVIDADES POR DESARROLLAR

1. Modelo y orden natural

Implementar el modelo y ordenar una copia por código ascendente usando su orden natural, sin proporcionar un comparador externo. Explicar qué representa el signo del resultado de compareTo().

2. Consultas con Comparator

Implementar las siguientes consultas. Cada criterio se aplica de izquierda a derecha; el siguiente solo interviene si existe empate en el anterior.

ID Orden requerido Requisito técnico
C1 Código ascendente. Comparable y ordenamiento natural.
C2 Nombre ascendente; código ascendente. Comparator con lambda de dos parámetros.
C3 Nota ascendente, sin desempate. comparingDouble y referencia a método.
C4 Nota descendente; nombre ascendente. reversed y thenComparing.
C5 Edad ascendente; nombre descendente. comparingInt y sentido independiente para el criterio secundario.
C6 Carrera ascendente; nota descendente; nombre ascendente; código ascendente. Composición de cuatro criterios.
C7 Nota ajustada descendente; nombre ascendente; código ascendente. Lambda que calcule Math.min(10.0, nota + 0.5) para estudiantes de Computacion y conserve la nota de las demás carreras.

En C7, calcular la clave sin modificar la nota del objeto. Mostrar tanto la nota original como la ajustada. No crear una clave artificial combinando números y sumas de caracteres.

3. Comparación de implementaciones

  • Implementar C2 también con comparing(), thenComparing() y referencias a métodos.
  • Verificar que ambas versiones producen exactamente la misma secuencia de códigos.
  • Explicar por qué invertir un comparador compuesto completo también invierte sus criterios de desempate. Relacionar la explicación con C4 y C5.
  • Explicar por qué comparar dos estudiantes por nota puede devolver cero aunque tengan códigos distintos.

4. Pruebas y estabilidad

  • Ejecutar las siete consultas sobre los 20 registros.
  • Comprobar que cada salida conserva los 20 códigos, sin pérdidas ni duplicaciones.
  • Verificar el orden mediante comparaciones entre elementos consecutivos.
  • Comprobar que la lista original mantiene su secuencia de códigos después de ejecutar todas las consultas.
  • Probar lista vacía, un solo estudiante y empates completos en los criterios usados.
  • Verificar la estabilidad de C3 mediante los códigos de los estudiantes que tienen nota 8.5.

5. Documentación y repositorio

Organizar el código en modelo, comparadores, datos de prueba y ejecución. Registrar commits funcionales para esas etapas, con mensajes que describan el cambio real.

Incluir instrucciones suficientes para compilar y ejecutar desde la terminal, además de la ejecución desde el IDE.
